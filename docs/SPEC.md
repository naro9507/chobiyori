# 個人事業主向け会計アプリ 仕様書（ドラフト v0.9）

個人事業主が業種を問わず使える会計デスクトップアプリの仕様。出発点として、実際に運用されている Excel 帳簿 2 冊（英語教室）を読み解き、そこから汎用的な要件を抽出した。

- 対象ブック A: `DCS accounts for 2014.xlsx`（英語教室の日英併記の仕訳帳。実運用の本体）
- 対象ブック B: `平成26年 DCS仕訳帳(1). 貸借対照表.xlsx`（旧様式の仕訳帳テンプレートと、申告用の集計シート）

> 税務上の取り扱い（按分・償却・控除要件・消費税など）は設計上の前提を書いたものであり、正しさと最新の制度への適合は税理士に確認すること。

---

## 1. 参考にした Excel 帳簿の解釈（出発点となる実例）

### 1.1 何をしている帳簿か

個人事業（英語教室）の **複式簿記の仕訳帳** を月別シートで付け、月次・年次で科目別に集計し、最終的に **青色申告決算書（損益計算書・貸借対照表）に転記する金額** を作っている。入力はすべて「番号」で行い、名称は VLOOKUP で引く方式。

### 1.2 シート構成と役割

| ブック | シート | 役割 | アプリでの対応 |
|---|---|---|---|
| A | `No.` | 4 つのマスタ（勘定科目 1〜 / 摘要 1〜 / 生徒 1〜 + 月謝額 / 店・会社 501〜） | マスタ管理 |
| A | `Jan.`〜`Dec.` | 月別仕訳帳 + 右側に集計パネル | 仕訳入力・各種帳票 |
| A | `Fee 授業料` | 生徒別の当月入金・返金一覧 | 月謝管理 |
| A | `Total` | 科目 × 12 か月の借方/貸方、前年末残高、年末残高、青色控除前所得 | 月次推移試算表・決算 |
| A | `原紙` / `example` | 月シートの雛形・記入例 | 不要（アプリが代替） |
| A | `出力` | 仕訳帳の印刷様式（1 仕訳 = 借方行 + 貸方行） | 仕訳帳 PDF |
| B | `コード` | 科目 101〜 / 摘要 201〜 / 相手先 300〜（五十音順）/ 顧客 1〜 | マスタ管理（検索で代替） |
| B | `1月`〜`12月` / `見本` | 月別仕訳帳（A と同じ思想の旧様式） | 同上 |
| B | `貸借対照表` | 科目 × 月の借方/貸方（上期・下期・通年）＝実質は合計残高試算表 | 月次推移試算表 |
| B | `申告金額` | 青色申告決算書の損益計算書 ①〜㉜ と貸借対照表（期首/期末）への転記値 | 決算書出力 |
| B | `Sheet2` | 領収証綴りなどの背表紙ラベル | 対象外 |

### 1.3 月シートの構造（ブック A）

**仕訳入力部（A〜N 列）**

1 行が 1 仕訳で、借方 1 科目と貸方 1 科目を持つ。

| 列 | 内容 | 入力 |
|---|---|---|
| day | 日（月と年はシート名・ファイル名が持つ） | 手入力 |
| No. / plus / 借方 | 借方科目の番号 → 英名・和名 | 番号のみ手入力 |
| No. / minus / 貸方 | 貸方科目の番号 → 英名・和名 | 番号のみ手入力 |
| money | 金額（円） | 手入力 |
| No. / purpose | 摘要の番号 → 英名・和名 | 番号のみ手入力（任意） |
| No. / students,shop,company | 相手先の番号。1〜 は生徒、501〜 は店・会社 | 番号のみ手入力（任意） |

**右側パネル**

| パネル | ロジック | 意味 |
|---|---|---|
| 家事按分メモ（electricity / gas / water → bank, school, private） | `school = bank × 50%`, `private = bank × 50%` | 自宅兼教室の光熱費などを事業分と家事分に割る計算。結果を見て「経費」と「事業主貸」の 2 仕訳を手で入力している |
| 科目別集計（No. / plus / minus） | `SUMIF(借方No列, 科目No, 金額列)` / 貸方も同様。最下行で借方合計 = 貸方合計を目視確認 | 月次の合計試算表 |
| 現金・預金残高（シート上端） | `現金残高 = 前月残高 + 現金の借方計 − 貸方計`。前月残高は手入力 | 現金出納帳・預金残高の代わり |
| 生徒別月謝（No. / NAME / school fees / repay / receipts） | `SUMPRODUCT(相手先=生徒No × 摘要=1(月謝) × 金額)`、返金は摘要 = 11（授業料戻し）、`receipts = fees − repay` | 生徒ごとの当月入金額 |

**ブック B の月シートに追加であるもの**: 売掛金の前月残、按分率が費目ごとに違う例（50/50、80/20、30/70）、現金出納（収入・支出・累計・差）。

### 1.4 年次集計と申告（`Total` / `申告金額`）

- `Total`: 各月パネルの借方計・貸方計を科目ごとに 12 か月並べ、`年末残高 = 前年末残高 + 年間借方 − 年間貸方`。収益・費用は年間の純額。
- 固定資産（建物・建物付属設備・工具器具備品・車両運搬具・構築物・土地）は期首/期末の簿価を手で記入し、減価償却費も手計算の値を記入。
- 借入金（複数の借入先）と利子割引料、未払金の残高を追跡。
- `申告金額` の損益計算書は、売上① → 売上原価②〜⑥ → 経費⑧〜㉛ → 計㉜ → 差引金額の順に並ぶ。経費には、決算書の既定科目のほかに任意科目（新聞図書費・支払手数料・販売促進費・車両費・教育訓練費）がある。
- `申告金額` の貸借対照表は、資産・負債の期首/期末を並べる。事業主貸・事業主借・元入金・青色申告特別控除前の所得金額を加えて、貸借を一致させている。

### 1.5 現行運用で起きている問題（アプリで解消すべき点）

読み解く中で、Excel 運用ゆえの不整合が実際に見つかった。

| # | 事象 | 原因 | アプリでの対策 |
|---|---|---|---|
| 1 | 月の借方合計と貸方合計が一致しない月がある（例: 9 月・10 月で差額 2,376 円） | 集計パネルの科目行と `No.` マスタの番号がずれている（買掛金/広告宣伝費の行に `#ERROR!`） | 複式の整合を DB 制約で保証。集計は仕訳から都度導出 |
| 2 | `Total` の普通預金の年末残高がマイナス表示 | 前年末残高を入れる列を間違えている | 期首残高は専用画面で入力し、繰越は自動 |
| 3 | 生徒別パネルの和名が別人の名前にずれている／旧ブックの顧客名が混入 | 雛形コピー時の貼り付けずれ | 名称は常にマスタから表示 |
| 4 | `#REF!`、外部ブック参照 `[1]コード!`、行ごとにばらばらな VLOOKUP 範囲 | シート複製の積み重ね | 数式を持たない |
| 5 | 行数上限（SUMIF は 85 行、月謝集計は 52 行まで）を超えると黙って集計から漏れる | 固定範囲の数式 | 上限なし |
| 6 | 前月残高・売掛残・繰越金を毎月手で転記 | シートが月ごとに独立 | 連続した帳簿として自動繰越 |
| 7 | 日付が「日」だけで、入力順もばらばら | シート構造 | 完全な日付を保持し日付順に表示 |
| 8 | 按分は電卓代わりのメモで、2 本の仕訳は手入力 | 仕組みがない | 按分ルールから自動で 2 行に分割 |
| 9 | 月謝の「誰が未納か」は一覧から目で探す | 入金額しか出ていない | 予定額（月謝額マスタ）と突き合わせて未入金を表示 |
| 10 | 見出しの年月・和暦が古いまま（`Junuary , 2007`、平成 20 年 等） | 手で書き換える運用 | 会計年度から自動表示 |

## 2. 製品コンセプト

**「個人事業主なら業種を問わず使える、番号でも打てる複式簿記の会計アプリ」**

英語教室の帳簿（第 1 章）は最初の実例・受け入れテストとして扱い、アプリ本体は特定業種に依存させない。帳簿から得た良い点は汎用機能として残し、教室固有の部分は「業種テンプレート」と「任意モジュール」に切り出す。

| Excel 帳簿にあったもの | 汎用化した形 |
|---|---|
| 教室用の 34 科目 | 青色申告決算書（一般用）準拠の標準科目 + 業種テンプレートで追加 |
| 生徒マスタ・月謝額 | 取引先（顧客）+ 定期売上プラン（月謝・会費・顧問料・サブスク等） |
| 生徒別月謝パネル | 顧客別の定期売上・入金管理（任意モジュール） |
| 店・会社マスタ（501〜） | 取引先（仕入先・支払先）。インボイス登録番号を保持 |
| 光熱費の 50% 按分メモ | 家事按分ルール（費目ごとの事業割合） |
| 番号入力 + VLOOKUP | コード入力（番号 / 名前検索の両対応） |
| 月シート・`Total` | 月次試算表・月次推移表 |
| `申告金額` | 青色申告決算書 / 収支内訳書の金額一覧 |

### 設計原則

1. コアは汎用にし、業種差はデータで吸収する。科目・摘要・定型仕訳・按分ルールをまとめた「業種テンプレート」を初期設定で選ぶ。コードに業種分岐を書かない。
2. 入力方法は 2 段構えにする。簿記に不慣れな人には「かんたん入力（収入 / 支出 / 振替）」を、慣れた人には「仕訳グリッド（番号入力）」を用意する。どちらで入力しても同じ仕訳データになる。
3. 集計値は保存しない。残高・試算表・決算書をすべて仕訳から導出し、手転記と不整合をなくす。
4. 使わない機能は見せない。消費税、在庫、売掛管理、定期売上は設定でオン/オフできる。
5. インターネット接続を前提にする。レシートの読み取りはオンラインの AI で行う。帳簿のデータは PC 内に暗号化して保存する。日本語 / 英語を切り替えられる。

### 対象ユーザーとスコープ

| 区分 | 内容 |
|---|---|
| 対象 | 事業所得のある個人事業主（サービス業、教室、小売、飲食、フリーランス、建設・一人親方 等）。青色申告（65 / 55 / 10 万円控除）と白色申告 |
| v1 に含む | 初期設定ウィザード、マスタ、かんたん入力・仕訳グリッド・複合仕訳、家事按分、定型仕訳、各種帳簿、期首残高と年度繰越、固定資産と減価償却、棚卸、青色申告決算書（一般用）/ 収支内訳書の金額一覧、税区分の記録、レシート OCR、カード明細 CSV 取込（アメックスほか）、自動仕訳ルール、証憑の添付、CSV/Excel 取込、CSV/PDF 出力、バックアップ/復元 |
| v1.x 候補 | 定期売上・入金管理、売掛/買掛の消込、消費税集計表（本則 / 簡易 / 2 割特例）、銀行明細 CSV の取込、スマホからのレシート送信、請求書・領収書の発行 |
| 対象外 | e-Tax 直接送信、確定申告書本体（所得控除等）の作成、消費税申告書の作成、不動産所得用・農業所得用の決算書、給与計算・年末調整、法人会計、銀行・カードの API 連携、帳簿データのクラウド保存、複数人同時利用 |

## 3. 機能仕様

### F0. 初期設定ウィザード

初回起動時に以下を順に設定する。後から設定画面で変更可能。

1. 事業者情報（屋号、氏名、住所、業種）
2. 申告区分: 青色（複式・65/55 万円）/ 青色（簡易・10 万円）/ 白色
3. 消費税: 免税 / 課税（本則・簡易・2 割特例）、インボイス登録番号、経理方式（v1 は税込経理のみ）
4. 業種テンプレートの選択 → 科目・摘要・定型仕訳・按分ルールを一括投入
5. 口座の登録（現金、預金口座、クレジットカード、電子マネー）
6. 開始年度と期首残高
7. 使う機能の選択（在庫、売掛/買掛、定期売上、家事按分）

### F1. マスタ管理

全マスタ共通で「コード・和名・英名・かな・並び順・有効/無効」を持つ。コードはユーザーが自由に採番でき、使用済みマスタは削除不可（無効化のみ）。

**F1-1 勘定科目**

- 標準セットは青色申告決算書（一般用）の科目に準拠。区分（資産 / 負債 / 資本 / 収益 / 売上原価 / 経費）と「決算書の行」を必ず持つ。

| 区分 | 標準科目 |
|---|---|
| 資産 | 現金、当座預金、定期預金、その他の預金（普通預金）、受取手形、売掛金、有価証券、棚卸資産、前払金、貸付金、建物、建物附属設備、機械装置、車両運搬具、工具器具備品、土地、構築物、事業主貸 |
| 負債・資本 | 支払手形、買掛金、借入金、未払金、前受金、預り金、貸倒引当金、事業主借、元入金 |
| 収益 | 売上高、家事消費等、雑収入 |
| 売上原価 | 期首商品棚卸高、仕入高、期末商品棚卸高 |
| 経費 | 租税公課、荷造運賃、水道光熱費、旅費交通費、通信費、広告宣伝費、接待交際費、損害保険料、修繕費、消耗品費、減価償却費、福利厚生費、給料賃金、外注工賃、利子割引料、地代家賃、貸倒金、雑費、専従者給与 |

- 任意の経費科目（例: 車両費、新聞図書費、支払手数料、販売促進費、教育訓練費、会議費）を追加できる。決算書の空欄行は 6 行なので、超える場合は「雑費に合算して出力」などの割当を促す。
- 補助科目として、科目の下に内訳を持てる（普通預金 → 口座別、借入金 → 借入先別、売掛金 → 得意先別、クレジットカード未払 → カード別）。元帳・残高は補助科目単位でも見られる。
- 科目ごとに既定の税区分、既定の按分ルールを設定できる。

**F1-2 摘要**

よく使う取引内容を登録する。既定の借方/貸方科目、税区分、按分ルール、取引先を紐付けられ、摘要を選ぶだけで仕訳が埋まる。

**F1-3 取引先**

顧客・仕入先・支払先・金融機関を 1 つのマスタで管理する（種別は複数選択可）。インボイス登録番号、既定の摘要、メモを持つ。個人顧客（生徒・会員など）も同じマスタに入れる。

**F1-4 家事按分ルール**

名前、事業割合（%）、端数処理を持つ。自宅兼事務所の家賃・光熱費・通信費・車両費などに使う。

**F1-5 業種テンプレート**

上記マスタの初期データ一式を指す。同梱候補は次のとおり: 汎用（標準）、サービス業・フリーランス、教室・スクール（第 1 章の帳簿が原型）、小売・物販、飲食、建設・一人親方。ユーザーは現在のマスタをテンプレートとして書き出し・読み込みできる。

### F2. 取引入力

内部では「取引（ヘッダ）+ 明細行」で保持し、各取引は借方合計 = 貸方合計を満たす。入力方法は 3 つ。

**F2-1 かんたん入力**

簿記を意識せずに入力できる。

- 種類を選ぶ: 収入 / 支出 / 口座間の振替 / 事業主の出し入れ。
- 入力項目: 日付、金額、内容（摘要 or 科目）、支払・入金口座、取引先、メモ。
- 例: 支出・消耗品費・現金 1,200 円 → `消耗品費 / 現金 1,200`。相手科目は口座から自動決定。
- 既存の収入・支出機能（`features/income`）はこの入力方法として再構成する。

**F2-2 仕訳グリッド**

Excel 帳簿と同じ手数で高速に入力できる。

- 月単位の表。列: 日 / 借方 / 貸方 / 金額 / 摘要 / 取引先 / 税区分 / メモ。
- 各コード欄は番号でも名前の一部（和・英・かな）でも入力可。Enter / Tab で次へ進み、行末で次行を自動追加。直前行の値を既定値にできる。
- フッタに当月の借方計・貸方計、主要口座の残高を常時表示。

**F2-3 複合仕訳**

借方・貸方が複数行になる取引（給与支払と源泉預り、売上と手数料の相殺、借入返済の元金 + 利息など）を入力する。貸借が一致するまで保存できない。

**F2-4 家事按分**

按分ルール付きの科目・摘要で支払額を入れると、事業分（経費）と家事分（事業主貸）の 2 行を自動生成する。割合は取引ごとに上書き可。取引時按分のほか、期末に年間合計へ一括で按分する方式も選べる。

**F2-5 定型仕訳・繰り返し**

よく使う取引をテンプレートとして登録できる。「毎月 N 日」などの繰り返しを設定でき、未登録分を候補として提示する（確認なしに自動記帳はしない）。過去取引のコピーも可。

- 候補は「候補を出しはじめる月」から、年度のうち今月（過去の年度なら 12 月）までの各月のうち、記録も見送りもしていない月。月にない日（31 日など）は月末にする。
- 記録するときに金額・日付を直せる（電気代のように毎月変わるもの）。按分の割合を持つ定型仕訳は、記録するときに事業分と家事分の 2 行に分ける。
- その月を見送ることも、見送りを取り消すこともできる。

**F2-6 共通ルール**

- バリデーション: 日付は当該年度内、金額は 1 円以上の整数、借方 ≠ 貸方、有効なマスタのみ。
- 修正・削除は変更履歴を残す。月締め・年締めでロックし、解除は明示操作 + 履歴記録。
- 検索: 期間・科目・取引先・摘要・金額・メモで絞り込み。

### F3. 消費税・インボイス対応

- 明細行ごとに税区分を記録する。区分は次の 8 つ。
  - 課税売上 10%
  - 課税売上 軽減 8%
  - 非課税売上
  - 不課税
  - 課税仕入 10%
  - 課税仕入 軽減 8%
  - 非課税仕入
  - 対象外
- 仕入先が適格請求書発行事業者かどうかも、明細行ごとに記録する。
- 免税事業者は税区分欄を非表示にできる（内部では「対象外」で保存）。途中で課税事業者になった年度から表示に切替。
- 税区分を選ばなければ、科目の既定の税区分で保存する。家事按分の家事分（事業主貸）は「対象外」にする。
- インボイスの印は、かんたん入力と定型仕訳では、取引先に登録番号があれば支払いの行に自動で付ける。複合仕訳では行ごとに選ぶ。免税の年度は付けない。
- v1 は税込経理で記録まで。税区分別の集計表（申告書作成の元資料）は v1.x。

### F4. 帳簿・照会

| 帳票 | 内容 |
|---|---|
| 仕訳帳 | 日付順。印刷は 1 取引を借方行・貸方行で表示 |
| 総勘定元帳 | 科目別・補助科目別の明細と残高 |
| 現金出納帳 / 預金出納帳 | 口座別の入金・出金・残高。実残高との照合欄 |
| 売掛帳 / 買掛帳 | 取引先別の発生・回収（支払）・残高 |
| 経費帳 | 経費科目別の明細 |
| 固定資産台帳 | F6-2 参照 |
| 合計残高試算表 | 月次・任意期間。貸借一致チェック |
| 月次推移表 | 科目 × 12 か月 + 期首 + 期末 |
| 取引先別・摘要別集計 | 売上・支出の内訳 |

- すべて期間指定、CSV / PDF 出力可。金額クリックで該当取引へドリルダウン。
- 白色・簡易簿記の利用者には、仕訳帳・元帳を隠して現金出納帳・経費帳・売上帳を中心に見せる。

### F5. 債権債務・定期売上（任意モジュール）

**F5-1 売掛・買掛**

発生時に `売掛金 / 売上`、入金時に `預金 / 売掛金` を記帳する。取引先別の残高と未回収一覧を表示する。期中は現金主義で記帳し、期末だけ未収・未払を計上する運用も選べる。

**F5-2 定期売上プラン**

月謝・会費・顧問料・保守料など毎月決まった売上を管理する（Excel 帳簿の月謝管理を汎用化）。

- 顧客ごとにプラン（名称、金額、周期、開始/終了月、状態: 有効・休止・終了）を登録。
- 入金登録: 顧客を選ぶと金額が入り、対象月を付けて仕訳化。返金は売上のマイナスとして登録。
- 月次一覧: 顧客 × （予定額 / 入金 / 返金 / 差引 / 状態）。年間マトリクスで未入金を強調。
- 顧客未指定の一括売上計上も許容し、「未割当の入金」として別枠表示する。

### F6. 決算

**F6-1 期首残高**

初年度のみ手入力する。貸借が一致しないと確定できない。開業初年度は開業費・元入金の入力ガイドを出す。

**F6-2 固定資産と減価償却**

- 資産ごとに: 名称、科目、取得日、取得価額、耐用年数、償却方法、事業専用割合、期首簿価、除却・売却日。
- 対応する償却: 定額法（既定）、定率法（届出がある場合）、一括償却資産（3 年均等）、少額減価償却資産の特例（青色・30 万円未満の即時償却）、月割計算、備忘価額 1 円。
- 年次で償却費を計算し決算仕訳を生成（確認後に確定）。事業専用割合に応じて経費と事業主貸に分ける。
- 耐用年数は主要資産の一覧から選択できるようにする（表はアプリに同梱し、年度ごとに更新可能なデータとして持つ）。

**F6-3 棚卸**

期末商品棚卸高を入力すると、売上原価（期首棚卸 + 仕入 − 期末棚卸）を計算し、翌期首へ繰り越す。在庫の数量管理はしない。

**F6-4 決算整理チェックリスト**

決算で必要な次の作業を一覧にし、済んだものに印を付けていく。

- 未収・未払・前払・前受の計上
- 家事按分の確定
- 減価償却
- 棚卸
- 貸倒引当金
- 現金・預金残高の実査照合
- 事業主貸借の確認

項目は申告区分と有効な機能に応じて出し分ける。

**F6-5 決算書の金額一覧**

- 青色申告決算書（一般用）では次の値を出す。
  - 損益計算書（①から青色申告特別控除前の所得金額まで）
  - 月別売上（仕入）金額
  - 給料賃金・専従者給与・地代家賃・利子割引料・税理士等報酬の内訳
  - 減価償却費の計算
  - 貸借対照表（期首 / 期末）
- 白色申告向けに、収支内訳書（一般用）の値を出す。
- 資産合計 = 負債・資本合計、損益計算書と貸借対照表の所得金額の一致を検証し、不一致なら原因候補を示す。
- 出力は「様式の項目順に並べた転記用の金額一覧（画面 + PDF）」。様式そのものへの印字や e-Tax データ出力は将来課題。
- 様式の行構成は年度ごとのデータとして持ち、様式改定に差し替えで対応できるようにする。

**F6-6 年度繰越**

資産・負債の期末残高を翌期首へ繰り越す。`翌期首元入金 = 期末元入金 + 青色控除前所得 + 事業主借 − 事業主貸`。マスタ・定型仕訳・固定資産・定期売上プランは引き継ぐ。

| 汎用 CSV 取込 | 列の対応付け（日付・借方・貸方・金額・摘要…）を画面で指定し、設定を保存して再利用する。F9-2 の形式エディタと同じ画面・同じ仕組みを使う。取込前にプレビューと検証（未定義コード、貸借不一致、重複）を必ず挟む |

| バックアップ / 復元 | 暗号化した単一ファイルに書き出す。終了時に自動でバックアップし、世代を保持する |

### F9. 取込受信箱（レシート OCR・カード明細 CSV の共通の受け皿）

レシート写真とカード明細は、どちらも「仕訳の候補」を作るだけで、直接は記帳しない。候補は受信箱に溜まり、ユーザーが確認・修正して確定した時点で取引になる。

- 一覧: 取込元（レシート / カード名）、日付、金額、店名、推定した科目・税区分、状態（未確認 / 確定済 / 対象外 / 重複の疑い）。
- 1 件ずつ確認する画面: 左に元データ（レシート画像 or 明細行）、右に仕訳フォーム。Enter で確定して次へ。
- 一括操作: 推定の確信度が高いものをまとめて確定、私用分をまとめて「対象外」または「事業主貸」に。
- 確定時に「次回から同じ店はこの科目にする」をルールとして保存できる（F9-3）。

**F9-1 レシート OCR**

| 段階 | 内容 |
|---|---|
| 取込 | 画像（JPEG / PNG / HEIC）・PDF をドラッグ&ドロップ、フォルダ指定、複数枚一括。スマホで撮った写真をPCに移して読む想定（スマホ連携は将来課題） |
| 前処理 | 傾き補正、トリミング、コントラスト調整。1 画像に複数レシートがある場合は分割を試みる |
| 読み取り | 画像を Gemini API に送り、結果を JSON で受け取る（下の「読み取りの方式」を参照） |
| 項目抽出 | 日付（和暦含む）、合計金額、店名、電話番号、インボイス登録番号（T + 13 桁）、税率別の対象額と税額（10% / 軽減 8%）、支払方法（現金 / カード / 電子マネー） |
| 仕訳推定 | 店名 → 取引先マスタ・自動仕訳ルール・過去の同じ店の仕訳から科目・摘要・税区分を推定。支払方法から貸方（現金 / カード未払金 / 事業主借）を推定 |
| 確認 | 抽出した各項目が画像のどこから読まれたかをハイライト。確信度が低い項目は色を変えて必ず目視させる |
| 保存 | 画像を証憑として取引に添付（暗号化して保存、ハッシュ値と取込日時を記録） |

- 税率が混在するレシート（食品 8% + 日用品 10%）は税率ごとに明細行を分ける。
- 合計と「税率別対象額の合計」が合わないなど、読み取り結果の自己検算に失敗したら確信度を下げる。
- 読み取れなかった場合も画像は残し、手入力で仕訳を付けられる。
- 精度目標（要検証）: 合計金額と日付は印字の鮮明なレシートで 9 割以上を自動で正しく読む。店名・科目推定は使い込むほどルールで改善する設計とし、初回精度には依存しない。

読み取りの方式は Gemini API（Google AI Studio）とする。端末内 OCR は使わない。メモリ 4GB の PC では、精度の出る OCR モデルを動かせないためである。

- 利用者は Google AI Studio で API キーを取得し、初期設定で登録する。キーがない間は、画像を証憑として添付して手入力する。
- 画像を送り、日付・金額・店名・登録番号・税率別内訳・支払方法を JSON で受け取る。
- API の呼び出しは Rust 側から行う。API キーは OS の資格情報ストアに保存し、画面側（WebView）・ログ・書き出しファイルに出さない。
- 送るのはレシート画像だけにする。帳簿・取引先マスタ・顧客名は送らない。
- 初期設定で次の 2 点を説明して同意を得る。送信先がどこか。無料枠では送信データがサービス改善に使われうること。
- 個人名が写った書類（領収書の宛名、請求書など）は送らずに手入力できる。送るかどうかは 1 件ずつ選べる。
- 接続が切れているときは画像を受信箱に溜め、接続後にまとめて読み取る。
- 無料枠の回数制限に達したら待ってから再試行し、利用者に残り件数を示す。
- モデル名は設定で変えられるようにする（提供側の改廃に備える）。
- 返ってきた値は必ず自己検算（合計と税率別内訳の一致、日付の妥当性）にかけ、利用者の確認を経てから仕訳にする。
- 読み取り部分は差し替え可能な構造にし、他の AI サービスへ乗り換えられるようにする。

**F9-2 カード明細 CSV 取込**

取込形式はユーザーが自分で作れる。これを中心機能とする。カード会社ごとの CSV の違いは「取込形式」というデータで定義し、コードにカード会社ごとの分岐を書かない。同梱プリセットも、ユーザーが作る形式と同じ仕組みで作る。

Visa / Mastercard / JCB は国際ブランドであり、CSV は発行会社ごとに異なる。どのカードでも使えるようにするには、この方式が最も確実である。

形式エディタでは、手元の明細ファイルを開き、実データのプレビューを見ながら次の順に設定する。

| 手順 | 設定内容 | 自動判定 |
|---|---|---|
| 1. ファイルを開く | CSV / TSV / Excel（xlsx）。文字コード（Shift_JIS / UTF-8）、区切り文字、引用符 | あり（手動で変更可） |
| 2. 範囲を決める | 見出し行の位置、先頭の読み飛ばし行数、末尾の合計行・注記行の除外（「日付として読めない行は無視」など） | あり |
| 3. 列に役割を割り当てる | プレビューの列をクリックして選ぶ: 利用日 / 金額 / 入金額・出金額（2 列に分かれている場合）/ 店名・内容 / メモ / 外貨額 / 利用者 / 無視 | 見出し名から推定 |
| 4. 値の読み方 | 日付の書式（西暦・和暦・区切り）、金額の書式（カンマ・¥・括弧）、符号の向き（利用がプラスかマイナスか） | あり |
| 5. 取込先 | 種別（カード / 銀行口座 / 電子マネー・決済サービス）と、対応する口座・カード | － |
| 6. 試し読み | 全行を読んだ結果を表示: 有効行数、無視した行、エラー行とその理由、日付範囲、合計額 | － |
| 7. 保存 | 名前を付けて保存。見出し行の内容を「この形式の目印」として記録 | － |

保存した形式は次のように扱う。

- 次回から同じ見出しのファイルを開くと、形式を自動で選ぶ。合う形式がなければエディタが開く。
- 列の増減や順番の変更で保存済みの形式と合わなくなったら、取込を止める。差分を示して形式の修正を促し、黙って誤った列を読むことはしない。
- 形式はファイル（JSON）として書き出し・読み込みでき、他の利用者と共有できる。個人情報は含まない。
- 必須の役割は「利用日・金額・店名（内容）」の 3 つだけ。

同梱プリセットは、アメリカン・エキスプレスを最初に用意し、利用者の多い発行会社を順次追加する。プリセットは実物のファイルで検証して作る。ユーザーは複製して自分用に修正できる。

カードは事前に登録する。カードごとに「未払金」の補助科目、引落口座、締め日・支払日、事業用 / 私用兼用の別を設定する。

仕訳は場面ごとに次の形にする。

| 場面 | 仕訳 | 補足 |
|---|---|---|
| 利用時 | `経費 / 未払金（カード名）` | 利用日で計上する |
| 引落時 | `未払金（カード名） / 普通預金` | 引落額と未払金残高の一致を確認する |
| 私用兼用カード | 事業分は上と同じ | 私用分は「対象外」にする運用と、全件取り込んで `事業主貸` にする運用を選べる |
| 個人名義の私用カードで事業経費を払った場合 | `経費 / 事業主借` | － |

次の特殊な行も扱う。

- 返品・取消（マイナス行）
- 年会費
- 分割・リボ手数料
- 海外利用（円換算額を採用し、外貨額はメモに残す）
- ポイント充当

重複を防ぐため、行ごとにハッシュ（カード・利用日・金額・店名・明細内の位置）を保存し、同じ行の再取込を弾く。期間が重なる CSV を読んでも二重にならない。

実装メモ（フェーズ 5）:

- 形式は JSON（文字コード・区切り文字・見出しの行・列の役割・金額の向き・目印の見出し）で持つ。プリセットも同じ形のファイル（`src-tauri/presets/`）。
- 重複を防ぐ鍵は「口座（と補助科目）・利用日・金額・そろえた店名・同じ内容の行の何回目か」。ファイルの中の行番号は使わない（期間の重なるファイルで位置がずれるため）。
- 返品・取消・ポイント充当はマイナスの行として読み、確定すると `未払金 / 科目` になる。海外利用は円の金額を使い、外貨額はメモに残す。年会費・手数料はふつうの行としてルールで科目を決める。
- 受信箱の候補に、同じ口座・同額・前後 3 日の取引がすでにあれば「同じ取引があるかも」と示す（手で入力した分との重なり）。レシートとの突合（F9-4）はフェーズ 6。
- 「確信度の高いもの」は、ルールか前回の確定から候補が出ているもの。まとめて確定できる。

**F9-3 自動仕訳ルール**

- 条件（店名に含まれる文字列・正規化後の一致、金額範囲、取込元）→ 結果（科目、補助科目、摘要、取引先、税区分、按分ルール、または「対象外」）。
- 店名は表記ゆれ（全角半角、カナ、支店名、決済代行の接頭辞）を正規化してから照合する。
- 確定操作から学習: 同じ店名を同じ科目で確定したら、次回から候補に出す。ルールは一覧で編集・無効化できる。
- レシート OCR とカード CSV で同じルールを共用する。

**F9-4 レシートとカード明細の突合（二重計上の防止）**

カード払いのレシートを OCR で登録し、同じ買い物がカード CSV にも現れると経費が二重になる。これを防ぐため、

- カード CSV の行ごとに、同じカード・近い日付（±数日）・同額の既存取引を探し、あれば「新規仕訳」ではなく「既存取引への紐付け」を提案する。
- 紐付いた取引は「レシートあり・明細あり」と表示。レシートがない明細行、明細に現れないカード払いレシートを一覧で確認できる。
- 現金払いのレシートは突合対象外。

| 検索 | ヘルプ全体をキーワードで探す。コマンドパレット（Ctrl+K）からも探せる |
| はじめての方へ | 使い始めの 3 ステップ（最初の設定、お金の出入りの記録、月に一度の残高確認） |
| やりたいことから探す | 「売上を記録したい」「レシートを読み込みたい」「決算したい」などの目的から、手順の説明と該当の画面へ進む |
| こんなときの入力例 | よくあるできごとと、その借方・貸方の組み合わせ。「この形で入力」を押すと、科目が入った状態で取引入力が開く |
| ことばの意味 | 仕訳、借方・貸方、勘定科目、事業主貸、事業主借、家事按分、減価償却などを、1〜2 文で説明する |
| キーボード操作 | ショートカットの一覧 |

入力例は、使っている業種テンプレートと有効な機能に合わせて出し分ける。

**F10-2 画面ごとの案内**

- 各画面の右上にヘルプのボタンを置き、その画面の説明を開く（F1 キーでも開く）。
- 会計の用語には印を付け、マウスを重ねるかキーボードで選ぶと意味を表示する。
- はじめて開いた画面では、何をする画面かを 1〜2 文で示す。一度閉じたら出さない。
- かんたん入力では借方・貸方という言葉を使わず、「何に使ったか」「どこから払ったか」で尋ねる。

**F10-3 文面の決まり**

- 専門用語を使うときは、最初に平易な言い換えを添える。
- 読みにくい漢字にはふりがなを付ける（仕訳、借方、貸方、按分など）。
- 税金の判断（経費にできるか、按分の割合、控除の要件）は説明しない。税理士か税務署に確認するよう案内する。
- 日本語と英語の両方を用意する。

### 4.1 画面の方針

画面はシンプルでわかりやすくし、目が疲れない配色を選ぶ。会計がはじめての人が迷わず使えることを優先する。

- 地は淡いグレー、文字はやわらかい黒にし、強い色は使わない。アクセントは彩度を抑えた 1 色にする。
- 枠線は細く薄くし、影はほとんど使わない。装飾のための要素は置かない。
- 数字は桁がそろう書体で表示する。
- 1 つの画面に置く情報を絞る。まず見るべき数字と、次にやることを上に置く。
- 会計の用語には、その場で意味を確かめられる説明を付ける（F10 を参照）。
- すべての操作をキーボードだけで行える。Ctrl+K のコマンドパレットから、画面の移動・仕訳の追加・検索を呼び出せる。
- ライト / ダークの切り替えを用意する。
- 空の画面には、次に何をすればよいかを短い文で示す。
- エラーや警告の文面は、責める調子にせず、直し方を先に書く。
- 動きは、画面の切り替えや確定の合図など、操作の結果を伝える最小限にとどめる。OS の「視覚効果を減らす」設定に従う。

画面のデザイン案は Claude のデザインキャンバスにある（ホーム、取引入力、取込受信箱、決算、ヘルプ）。

| `partners` | id, code, name_ja, name_en, kana, is_customer, is_vendor, invoice_registration_no, memo, is_active |

| `journal_lines` | id, transaction_id, line_no, side（debit/credit）, account_id, sub_account_id, amount, tax_category, is_qualified_invoice, purpose_id, partner_id, target_month, memo |

| `recurring_plans` | id, partner_id, name, amount, cycle, start_month, end_month, status（定期売上） |
| `opening_balances` | fiscal_year, account_id, sub_account_id, amount |
| `fixed_assets` | id, account_id, name, acquired_on, cost, useful_life, method, business_percent, opening_book_value, disposed_on |
| `inventories` | fiscal_year, closing_amount |
| `statement_layouts` | year, form（blue_general/white_general）, line_no, label, 対応科目（様式改定に備えデータ化） |
| `cards` | id, name, issuer, payable_sub_account_id, settlement_account_id, closing_day, payment_day, usage（business/mixed） |
| `import_profiles` | id, name, kind（card/bank/emoney/journal）, file_type, encoding, delimiter, header_row, skip_rows, row_filter_json, column_map_json, date_format, amount_format, amount_sign, detect_signature, is_preset, version |
| `import_batches` | id, source（receipt/card_csv）, card_id, profile_id, file_name, file_hash, imported_at |
| `import_items` | id, batch_id, row_hash, raw_json, date, amount, merchant_raw, merchant_normalized, suggested_json, confidence, status（pending/confirmed/excluded/duplicate）, transaction_id |
| `attachments` | id, transaction_id, import_item_id, file_path, mime, sha256, added_at（証憑。暗号化して保存） |
| `ocr_results` | attachment_id, engine, engine_version, text, fields_json（各項目の値・位置・確信度） |
| `auto_rules` | id, match_type, pattern, amount_min, amount_max, source, result_json, hit_count, is_active |
| `month_locks` | fiscal_year, month, locked_at |
| `audit_logs` | id, entity, entity_id, action, before_json, after_json, at |
| `settings` | key, value（既存） |

- 明細は借方行・貸方行を別レコードで持つ（複合仕訳に対応するため）。単一仕訳のグリッド表示は借方 1 行 + 貸方 1 行の取引を 1 行に畳んで見せる。
- 既存の `incomes` / `expenses` テーブルは廃止し、かんたん入力の取引として `transactions` / `journal_lines` に統合する。
- 集計値（月次合計・残高）は保存せず、常に仕訳と期首残高から計算する。

### 計算ルール

| 値 | 定義 |
|---|---|
| 取引の整合 | 取引ごとに 借方行の合計 = 貸方行の合計 |
| 資産の残高 | 期首 + 借方計 − 貸方計 |
| 負債・資本の残高 | 期首 + 貸方計 − 借方計 |
| 収益 / 費用の期間額 | 貸方計 − 借方計 / 借方計 − 貸方計 |
| 売上原価 | 期首棚卸 + 仕入 − 期末棚卸 |
| 青色控除前所得 | 収益計 − 売上原価 − 経費計 |
| 按分 | 事業分 = 端数処理(支払額 × 事業割合)、家事分 = 支払額 − 事業分 |
| 定期売上の受取額 | 対象顧客・対象月の売上計 − 返金計 |

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| ネットワーク | インターネット接続を前提にする。使うのはレシートの読み取り（Gemini API）とアプリの自動更新。帳簿のデータは PC 内に保存し、外部には送らない。接続が切れても、入力・帳簿・決算・CSV 取込・出力は動く |
| データ保護 | DB は SQLCipher で暗号化する。バックアップも暗号化する。API キーは OS の資格情報ストアに保存する。ログに個人名・金額を出さない |
| 整合性 | 取引の登録・按分・決算仕訳の生成は DB トランザクションで実行する。貸借一致を制約と自動テストで保証する |
| 性能 | メモリ 4GB の PC で、年 1 万取引でも入力・集計とも体感できる待ちがない。一覧は表示分だけ描画し、集計は SQL で行う。レシートの読み取りはバックグラウンドで処理して入力操作を止めない |
| 動作環境 | メモリ 4GB・低速な CPU・HDD の PC を下限とする。アプリのメモリ使用量は常用時 300MB 以下を目標にする。Tauri は OS 標準の WebView を使うため、Chromium を同梱する Electron より軽い |
| 制度変更への追従 | 決算書の行構成、税率、耐用年数表、控除額はコードに埋め込まず、年度別データとして持つ |
| i18n | 全ラベル・帳票見出しを日英対応にする。マスタ名称は日英 2 項目を持つ |
| 対応 OS | `docs/PLATFORM_SUPPORT.md` に従う |
| テスト | 計算ロジック（集計・按分・償却・棚卸・繰越）は Rust 側に置き、`cargo test` で単体テストする。画面は Vitest でテストする。第 1 章の 2014 年帳簿を取り込み、年次集計が一致することを受け入れテストの 1 つにする（個人名は匿名化したフィクスチャを使用） |

## 7. 技術構成と既存実装からの移行方針

### 7.1 技術構成

Electron をやめ、Tauri v2 に移行する。バックエンドは Rust で書く。画面は React を使い続けるが、重い React Admin と MUI は外す。選定の基準は「軽くて速いこと」「メモリを使わないこと」「モダンで、作っていて楽しい技術であること」の 3 つ。遊び心は開発に使う技術の話であり、製品の画面には持ち込まない。

| 層 | 採用技術 | 役割 |
|---|---|---|
| シェル | Tauri v2 | ウィンドウ、ファイルダイアログ、自動更新、インストーラ |
| バックエンド | Rust | DB アクセス、会計の計算、取込・出力、Gemini API の呼び出し |
| 画面 | React 19 + Vite + TypeScript | 入力と表示だけを担う。ライブラリは下の表を参照 |
| 画面とバックエンドの接続 | Tauri コマンド（`invoke`） | 型は Rust から TypeScript へ自動生成する |
| DB | SQLite + SQLCipher（`rusqlite`） | マイグレーションは SQL ファイルで管理する |

画面側のライブラリは次のとおり。部品は「必要なものだけコードとして取り込む」方式を選び、配布サイズとメモリを抑える。

| 用途 | 採用 | 補足 |
|---|---|---|
| スタイル | Tailwind CSS v4 | CSS-in-JS（Emotion）は使わない |
| UI 部品 | shadcn/ui | 使う部品だけをプロジェクトに取り込む。MUI は使わない |
| アイコン | lucide-react | 使うアイコンだけがビルドに含まれる |
| 画面遷移 | TanStack Router | 型の付いたルーティング |
| バックエンド呼び出しとキャッシュ | TanStack Query | Tauri コマンドの結果を保持し、更新後に再取得する |
| 表 | TanStack Table + TanStack Virtual | 見えている行だけを描画する（仕訳グリッド、元帳、受信箱） |
| フォーム | React Hook Form + Zod | 入力の検証 |
| 状態管理 | Zustand | 画面をまたぐ少量の状態だけに使う |
| コマンドパレット | cmdk | キーボード操作の入口 |
| 再描画の削減 | React Compiler | 手書きのメモ化を減らす |
| 整形・検査 | Biome | 現行を引き継ぐ |

画面側では次の依存を外す。

- `react-admin`
- `@mui/material`、`@mui/icons-material`
- `@emotion/react`、`@emotion/styled`
- `react-router-dom`

Rust 側で使う主なライブラリの候補は次のとおり。採用前に、日本語と Windows での動作を検証する。

| 用途 | 候補 |
|---|---|
| CSV 読み書き・文字コード変換（Shift_JIS） | `csv`、`encoding_rs` |
| Excel 取込 | `calamine` |
| Excel 出力 | `rust_xlsxwriter` |
| PDF 出力（日本語フォント埋め込み） | `krilla`（フォントは同梱せず、PC の游ゴシック・メイリオ・ヒラギノなどを使い、使った文字だけを埋め込む。埋め込みを禁じたフォントは使わない） |
| HTTP（Gemini API） | `reqwest` |
| API キーの保存 | `keyring` |
| 自動更新 | `tauri-plugin-updater` |

### 7.3 移行で変わること

- `apps/main/main.js`（Electron メインプロセス）を廃止し、`src-tauri/` に置き換える。
- Prisma は Node.js 用のため廃止する。スキーマは SQL のマイグレーションに書き直す。
- 次の依存を外す。
  - `electron`、`electron-builder`、`electron-updater`
  - `better-sqlite3`、`@journeyapps/sqlcipher`
  - `prisma`、`@prisma/client`
- `pages/admin`（React Admin の画面）は廃止し、shadcn/ui と TanStack Table で作り直す。
- 画面側の `*.service.ts` にある DB 操作とビジネスロジックを Rust に移す。画面側には、コマンドを呼ぶ薄い層と表示用の型だけを残す。
- `features/income`（単式の収入記録）は `features/journal` に統合し、かんたん入力の 1 モードとして残す。
- 画面側には次の feature を置く。
  - `setup`（初期設定）
  - `master`
  - `journal`
  - `ledger`（帳簿・集計）
  - `closing`（決算）
  - `tax`（税区分）
  - `receivable`（売掛・定期売上）
  - `inbox`（取込受信箱・自動仕訳ルール）
  - `import-export`
  - `backup`
- Windows では WebView2 が必要になる。Windows 11 には標準で入っている。Windows 10 向けには、インストーラに導入処理を含める。

| 8 | バックアップ / 復元、暗号化、月締め、変更履歴、業種テンプレート追加 | 配布可能（v1） |
| 9 | 定期売上・売掛買掛の消込、消費税集計表、銀行明細 CSV 取込 | v1.x |

## 9. 確認したい事項

1. **想定ユーザーの簿記レベル**: かんたん入力を主にするか、仕訳グリッドを主にするか。初期画面と用語（借方/貸方を見せるか）が変わる。
2. **白色申告・簡易簿記（10 万円控除）への対応**: v1 から必要か、まず青色・複式（65 / 55 万円）に絞るか。
3. **消費税**: v1 は「税区分を記録するだけ」でよいか。課税事業者向けの集計表まで v1 に入れるか。税抜経理は不要という前提でよいか。
4. **決算書の出力形態**: 転記用の金額一覧で足りるか。e-Tax 用データ出力（65 万円控除の要件に関わる）を将来必須とするか。
5. **同梱する業種テンプレート**: 最初に用意する業種と、その科目・摘要の監修を誰がするか。
6. **配布形態**: 自分用 → 身近な事業主に配布 → 一般公開、のどこまでを想定するか。サポート・制度改定への追従の重さが変わる。
7. **1 つのアプリで複数の事業者データを扱うか**（データファイルの切替）。
8. **対応 OS**: 現状 Windows は WSL2 前提だが、一般の個人事業主向けならネイティブ対応が必要になる。
9. **対応するカード**: 形式はユーザーが自作できるため、どのカードでも取り込める。そのうえでプリセットとして同梱したい発行会社はどこか。形式エディタの動作確認用に、アメックスの実物 CSV（個人情報を伏せたもの）を提供してもらえるか。
10. **カードの使い方**: 事業専用カードか、私用と兼用か。兼用の場合、私用分は取り込まないか、事業主貸として記帳するか。
11. **レシート読み取り**: Gemini API（Google AI Studio の無料枠）を使う。利用者は各自 API キーを取得する。無料枠の利用規約（送信データの扱い、回数制限）は変わりうるため、公開前に再確認する。
12. **レシート原本**: 紙を保管し続ける前提でよいか。電子保存だけで済ませたい場合はスキャナ保存要件への対応が必要になる。
13. **帳簿の保存方法**: 帳簿を紙に印刷して保存するか、電子データのまま保存するか。電子データで保存する場合と、65 万円控除を「優良な電子帳簿」で受ける場合は、電子帳簿保存法の要件を税理士に確認する。
14. **「全てオンライン」の範囲**: 本書では「接続を前提にし、レシート読み取りと自動更新に使う。帳簿のデータは PC 内に保存する」と解釈した。帳簿をクラウドに保存して複数の端末から使いたい場合は、サーバーと認証が必要になり、構成が大きく変わる。
15. **インボイスを登録した年の消費税**: 年の途中でインボイスの登録をした年は、登録日の前は免税事業者、登録日からは課税事業者になる。いまは年度ごとに消費税の区分を 1 つだけ持つ（`fiscal_years.tax_status`）。登録日を記録して年の途中で扱いを切り替える必要があるか、その年の帳簿をどう付ければよいかを税理士に確認する。2 割特例を使える年の範囲もあわせて確認する。
