# 個人事業主向け会計アプリ 仕様書（ドラフト v0.2）

個人事業主が業種を問わず使える会計デスクトップアプリの仕様。出発点として、実際に運用されている Excel 帳簿 2 冊（英語教室）を読み解き、そこから汎用的な要件を抽出した。

- 対象ブック A: `DCS accounts for 2014.xlsx`（英語教室の日英併記の仕訳帳。実運用の本体）
- 対象ブック B: `平成26年 DCS仕訳帳(1). 貸借対照表.xlsx`（旧様式の仕訳帳テンプレートと、申告用の集計シート）

> 税務上の取り扱い（按分・償却・控除要件・消費税など）は設計上の前提を書いたものであり、正しさと最新の制度への適合は税理士に確認すること。

---

## 1. 参考にした Excel 帳簿の解釈（出発点となる実例）

### 1.1 何をしている帳簿か

個人事業（英語教室）の **複式簿記の仕訳帳** を月別シートで付け、月次・年次で科目別に集計し、最終的に **青色申告決算書（損益計算書・貸借対照表）に転記する金額** を作っている。入力はすべて「番号」で行い、名称は VLOOKUP で引く方式。

### 1.2 シート構成と役割

| ブック | シート | 役割 | アプリでの対応 |
|---|---|---|---|
| A | `No.` | 4 つのマスタ（勘定科目 1〜 / 摘要 1〜 / 生徒 1〜 + 月謝額 / 店・会社 501〜） | マスタ管理 |
| A | `Jan.`〜`Dec.` | 月別仕訳帳 + 右側に集計パネル | 仕訳入力・各種帳票 |
| A | `Fee 授業料` | 生徒別の当月入金・返金一覧 | 月謝管理 |
| A | `Total` | 科目 × 12 か月の借方/貸方、前年末残高、年末残高、青色控除前所得 | 月次推移試算表・決算 |
| A | `原紙` / `example` | 月シートの雛形・記入例 | 不要（アプリが代替） |
| A | `出力` | 仕訳帳の印刷様式（1 仕訳 = 借方行 + 貸方行） | 仕訳帳 PDF |
| B | `コード` | 科目 101〜 / 摘要 201〜 / 相手先 300〜（五十音順）/ 顧客 1〜 | マスタ管理（検索で代替） |
| B | `1月`〜`12月` / `見本` | 月別仕訳帳（A と同じ思想の旧様式） | 同上 |
| B | `貸借対照表` | 科目 × 月の借方/貸方（上期・下期・通年）＝実質は合計残高試算表 | 月次推移試算表 |
| B | `申告金額` | 青色申告決算書の損益計算書 ①〜㉜ と貸借対照表（期首/期末）への転記値 | 決算書出力 |
| B | `Sheet2` | 領収証綴りなどの背表紙ラベル | 対象外 |

### 1.3 月シートの構造（ブック A）

**仕訳入力部（A〜N 列）** — 1 行 = 借方 1 科目 : 貸方 1 科目の単一仕訳

| 列 | 内容 | 入力 |
|---|---|---|
| day | 日（月と年はシート名・ファイル名が持つ） | 手入力 |
| No. / plus / 借方 | 借方科目の番号 → 英名・和名 | 番号のみ手入力 |
| No. / minus / 貸方 | 貸方科目の番号 → 英名・和名 | 番号のみ手入力 |
| money | 金額（円） | 手入力 |
| No. / purpose | 摘要の番号 → 英名・和名 | 番号のみ手入力（任意） |
| No. / students,shop,company | 相手先の番号。1〜 は生徒、501〜 は店・会社 | 番号のみ手入力（任意） |

**右側パネル**

| パネル | ロジック | 意味 |
|---|---|---|
| 家事按分メモ（electricity / gas / water → bank, school, private） | `school = bank × 50%`, `private = bank × 50%` | 自宅兼教室の光熱費などを事業分と家事分に割る計算。結果を見て「経費」と「事業主貸」の 2 仕訳を手で入力している |
| 科目別集計（No. / plus / minus） | `SUMIF(借方No列, 科目No, 金額列)` / 貸方も同様。最下行で借方合計 = 貸方合計を目視確認 | 月次の合計試算表 |
| 現金・預金残高（シート上端） | `現金残高 = 前月残高 + 現金の借方計 − 貸方計`。前月残高は手入力 | 現金出納帳・預金残高の代わり |
| 生徒別月謝（No. / NAME / school fees / repay / receipts） | `SUMPRODUCT(相手先=生徒No × 摘要=1(月謝) × 金額)`、返金は摘要 = 11（授業料戻し）、`receipts = fees − repay` | 生徒ごとの当月入金額 |

**ブック B の月シートに追加であるもの**: 売掛金の前月残、按分率が費目ごとに違う例（50/50、80/20、30/70）、現金出納（収入・支出・累計・差）。

### 1.4 年次集計と申告（`Total` / `申告金額`）

- `Total`: 各月パネルの借方計・貸方計を科目ごとに 12 か月並べ、`年末残高 = 前年末残高 + 年間借方 − 年間貸方`。収益・費用は年間の純額。
- 固定資産（建物・建物付属設備・工具器具備品・車両運搬具・構築物・土地）は期首/期末の簿価を手で記入し、減価償却費も手計算の値を記入。
- 借入金（複数の借入先）と利子割引料、未払金の残高を追跡。
- `申告金額`: 損益計算書は 売上① → 売上原価②〜⑥ → 経費⑧〜㉛（決算書の既定科目 + 任意科目: 新聞図書費・支払手数料・販売促進費・車両費・教育訓練費）→ 計㉜ → 差引金額。貸借対照表は資産・負債の期首/期末、事業主貸・事業主借・元入金・青色申告特別控除前の所得金額で貸借を一致させている。

### 1.5 現行運用で起きている問題（アプリで解消すべき点）

読み解く中で、Excel 運用ゆえの不整合が実際に見つかった。

| # | 事象 | 原因 | アプリでの対策 |
|---|---|---|---|
| 1 | 月の借方合計と貸方合計が一致しない月がある（例: 9 月・10 月で差額 2,376 円） | 集計パネルの科目行と `No.` マスタの番号がずれている（買掛金/広告宣伝費の行に `#ERROR!`） | 複式の整合を DB 制約で保証。集計は仕訳から都度導出 |
| 2 | `Total` の普通預金の年末残高がマイナス表示 | 前年末残高を入れる列を間違えている | 期首残高は専用画面で入力し、繰越は自動 |
| 3 | 生徒別パネルの和名が別人の名前にずれている／旧ブックの顧客名が混入 | 雛形コピー時の貼り付けずれ | 名称は常にマスタから表示 |
| 4 | `#REF!`、外部ブック参照 `[1]コード!`、行ごとにばらばらな VLOOKUP 範囲 | シート複製の積み重ね | 数式を持たない |
| 5 | 行数上限（SUMIF は 85 行、月謝集計は 52 行まで）を超えると黙って集計から漏れる | 固定範囲の数式 | 上限なし |
| 6 | 前月残高・売掛残・繰越金を毎月手で転記 | シートが月ごとに独立 | 連続した帳簿として自動繰越 |
| 7 | 日付が「日」だけで、入力順もばらばら | シート構造 | 完全な日付を保持し日付順に表示 |
| 8 | 按分は電卓代わりのメモで、2 本の仕訳は手入力 | 仕組みがない | 按分ルールから自動で 2 行に分割 |
| 9 | 月謝の「誰が未納か」は一覧から目で探す | 入金額しか出ていない | 予定額（月謝額マスタ）と突き合わせて未入金を表示 |
| 10 | 見出しの年月・和暦が古いまま（`Junuary , 2007`、平成 20 年 等） | 手で書き換える運用 | 会計年度から自動表示 |

## 2. 製品コンセプト

**「個人事業主なら業種を問わず使える、番号でも打てる複式簿記の会計アプリ」**

英語教室の帳簿（第 1 章）は最初の実例・受け入れテストとして扱い、アプリ本体は特定業種に依存させない。帳簿から得た良い点は汎用機能として残し、教室固有の部分は「業種テンプレート」と「任意モジュール」に切り出す。

| Excel 帳簿にあったもの | 汎用化した形 |
|---|---|
| 教室用の 34 科目 | 青色申告決算書（一般用）準拠の標準科目 + 業種テンプレートで追加 |
| 生徒マスタ・月謝額 | 取引先（顧客）+ 定期売上プラン（月謝・会費・顧問料・サブスク等） |
| 生徒別月謝パネル | 顧客別の定期売上・入金管理（任意モジュール） |
| 店・会社マスタ（501〜） | 取引先（仕入先・支払先）。インボイス登録番号を保持 |
| 光熱費の 50% 按分メモ | 家事按分ルール（費目ごとの事業割合） |
| 番号入力 + VLOOKUP | コード入力（番号 / 名前検索の両対応） |
| 月シート・`Total` | 月次試算表・月次推移表 |
| `申告金額` | 青色申告決算書 / 収支内訳書の金額一覧 |

### 設計原則

1. **コアは汎用、業種差はデータで吸収** — 科目・摘要・定型仕訳・按分ルールをまとめた「業種テンプレート」を初期設定で選ぶ。コードに業種分岐を書かない。
2. **入力は 2 段構え** — 簿記に不慣れな人向けの「かんたん入力（収入 / 支出 / 振替）」と、慣れた人向けの「仕訳グリッド（番号入力）」。どちらも同じ仕訳データになる。
3. **集計値は持たない** — 残高・試算表・決算書はすべて仕訳から導出し、手転記と不整合をなくす。
4. **使わない機能は見せない** — 消費税、在庫、売掛管理、定期売上は設定でオン/オフ。
5. **完全オフライン・ローカル保存・暗号化**。日本語 / 英語切替。

### 対象ユーザーとスコープ

| 区分 | 内容 |
|---|---|
| 対象 | 事業所得のある個人事業主（サービス業、教室、小売、飲食、フリーランス、建設・一人親方 等）。青色申告（65 / 55 / 10 万円控除）と白色申告 |
| v1 に含む | 初期設定ウィザード、マスタ、かんたん入力・仕訳グリッド・複合仕訳、家事按分、定型仕訳、各種帳簿、期首残高と年度繰越、固定資産と減価償却、棚卸、青色申告決算書（一般用）/ 収支内訳書の金額一覧、税区分の記録、CSV/Excel 取込、CSV/PDF 出力、バックアップ/復元 |
| v1.x 候補 | 定期売上・入金管理、売掛/買掛の消込、消費税集計表（本則 / 簡易 / 2 割特例）、銀行・カード明細 CSV の取込と自動仕訳ルール、証憑（領収書画像）の添付、請求書・領収書の発行 |
| 対象外 | e-Tax 直接送信、確定申告書本体（所得控除等）の作成、消費税申告書の作成、不動産所得用・農業所得用の決算書、給与計算・年末調整、法人会計、オンライン連携・複数人同時利用 |

## 3. 機能仕様

### F0. 初期設定ウィザード

初回起動時に以下を順に設定する。後から設定画面で変更可能。

1. 事業者情報（屋号、氏名、住所、業種）
2. 申告区分: 青色（複式・65/55 万円）/ 青色（簡易・10 万円）/ 白色
3. 消費税: 免税 / 課税（本則・簡易・2 割特例）、インボイス登録番号、経理方式（v1 は税込経理のみ）
4. 業種テンプレートの選択 → 科目・摘要・定型仕訳・按分ルールを一括投入
5. 口座の登録（現金、預金口座、クレジットカード、電子マネー）
6. 開始年度と期首残高
7. 使う機能の選択（在庫、売掛/買掛、定期売上、家事按分）

### F1. マスタ管理

全マスタ共通で「コード・和名・英名・かな・並び順・有効/無効」を持つ。コードはユーザーが自由に採番でき、使用済みマスタは削除不可（無効化のみ）。

**F1-1 勘定科目**

- 標準セットは青色申告決算書（一般用）の科目に準拠。区分（資産 / 負債 / 資本 / 収益 / 売上原価 / 経費）と「決算書の行」を必ず持つ。

| 区分 | 標準科目 |
|---|---|
| 資産 | 現金、当座預金、定期預金、その他の預金（普通預金）、受取手形、売掛金、有価証券、棚卸資産、前払金、貸付金、建物、建物附属設備、機械装置、車両運搬具、工具器具備品、土地、構築物、事業主貸 |
| 負債・資本 | 支払手形、買掛金、借入金、未払金、前受金、預り金、貸倒引当金、事業主借、元入金 |
| 収益 | 売上高、家事消費等、雑収入 |
| 売上原価 | 期首商品棚卸高、仕入高、期末商品棚卸高 |
| 経費 | 租税公課、荷造運賃、水道光熱費、旅費交通費、通信費、広告宣伝費、接待交際費、損害保険料、修繕費、消耗品費、減価償却費、福利厚生費、給料賃金、外注工賃、利子割引料、地代家賃、貸倒金、雑費、専従者給与 |

- 任意の経費科目（例: 車両費、新聞図書費、支払手数料、販売促進費、教育訓練費、会議費）を追加できる。決算書の空欄行は 6 行なので、超える場合は「雑費に合算して出力」などの割当を促す。
- **補助科目**: 科目の下に内訳を持てる（普通預金 → 口座別、借入金 → 借入先別、売掛金 → 得意先別、クレジットカード未払 → カード別）。元帳・残高は補助科目単位でも見られる。
- 科目ごとに既定の税区分、既定の按分ルールを設定できる。

**F1-2 摘要** — よく使う取引内容。既定の借方/貸方科目、税区分、按分ルール、取引先を紐付けられ、摘要を選ぶだけで仕訳が埋まる。

**F1-3 取引先** — 顧客・仕入先・支払先・金融機関を 1 つのマスタで管理（種別は複数選択可）。インボイス登録番号、既定の摘要、メモを持つ。個人顧客（生徒・会員など）も同じマスタに入れる。

**F1-4 家事按分ルール** — 名前、事業割合（%）、端数処理。自宅兼事務所の家賃・光熱費・通信費・車両費などに使う。

**F1-5 業種テンプレート** — 上記マスタの初期データ一式。同梱候補: 汎用（標準）、サービス業・フリーランス、教室・スクール（第 1 章の帳簿が原型）、小売・物販、飲食、建設・一人親方。ユーザーは現在のマスタをテンプレートとして書き出し・読み込みできる。

### F2. 取引入力

内部では「取引（ヘッダ）+ 明細行」で保持し、各取引は借方合計 = 貸方合計を満たす。入力方法は 3 つ。

**F2-1 かんたん入力** — 簿記を意識しない入力

- 種類を選ぶ: 収入 / 支出 / 口座間の振替 / 事業主の出し入れ。
- 入力項目: 日付、金額、内容（摘要 or 科目）、支払・入金口座、取引先、メモ。
- 例: 支出・消耗品費・現金 1,200 円 → `消耗品費 / 現金 1,200`。相手科目は口座から自動決定。
- 既存の収入・支出機能（`features/income`）はこの入力方法として再構成する。

**F2-2 仕訳グリッド** — Excel 帳簿と同じ手数の高速入力

- 月単位の表。列: 日 / 借方 / 貸方 / 金額 / 摘要 / 取引先 / 税区分 / メモ。
- 各コード欄は番号でも名前の一部（和・英・かな）でも入力可。Enter / Tab で次へ進み、行末で次行を自動追加。直前行の値を既定値にできる。
- フッタに当月の借方計・貸方計、主要口座の残高を常時表示。

**F2-3 複合仕訳** — 借方・貸方が複数行になる取引（給与支払と源泉預り、売上と手数料の相殺、借入返済の元金 + 利息など）。貸借が一致するまで保存できない。

**F2-4 家事按分** — 按分ルール付きの科目・摘要で支払額を入れると、事業分（経費）と家事分（事業主貸）の 2 行を自動生成する。割合は取引ごとに上書き可。取引時按分のほか、期末に年間合計へ一括で按分する方式も選べる。

**F2-5 定型仕訳・繰り返し** — よく使う取引をテンプレート登録。「毎月 N 日」などの繰り返しを設定でき、未登録分を候補として提示する（確認なしに自動記帳はしない）。過去取引のコピーも可。

**F2-6 共通ルール**

- バリデーション: 日付は当該年度内、金額は 1 円以上の整数、借方 ≠ 貸方、有効なマスタのみ。
- 修正・削除は変更履歴を残す。月締め・年締めでロックし、解除は明示操作 + 履歴記録。
- 検索: 期間・科目・取引先・摘要・金額・メモで絞り込み。

### F3. 消費税・インボイス対応

- 明細行ごとに税区分を記録: 課税売上 10% / 軽減 8% / 非課税売上 / 不課税 / 課税仕入 10% / 軽減 8% / 非課税仕入 / 対象外、および仕入先が適格請求書発行事業者かどうか。
- 免税事業者は税区分欄を非表示にできる（内部では「対象外」で保存）。途中で課税事業者になった年度から表示に切替。
- v1 は税込経理で記録まで。税区分別の集計表（申告書作成の元資料）は v1.x。

### F4. 帳簿・照会

| 帳票 | 内容 |
|---|---|
| 仕訳帳 | 日付順。印刷は 1 取引を借方行・貸方行で表示 |
| 総勘定元帳 | 科目別・補助科目別の明細と残高 |
| 現金出納帳 / 預金出納帳 | 口座別の入金・出金・残高。実残高との照合欄 |
| 売掛帳 / 買掛帳 | 取引先別の発生・回収（支払）・残高 |
| 経費帳 | 経費科目別の明細 |
| 固定資産台帳 | F6-2 参照 |
| 合計残高試算表 | 月次・任意期間。貸借一致チェック |
| 月次推移表 | 科目 × 12 か月 + 期首 + 期末 |
| 取引先別・摘要別集計 | 売上・支出の内訳 |

- すべて期間指定、CSV / PDF 出力可。金額クリックで該当取引へドリルダウン。
- 白色・簡易簿記の利用者には、仕訳帳・元帳を隠して現金出納帳・経費帳・売上帳を中心に見せる。

### F5. 債権債務・定期売上（任意モジュール）

**F5-1 売掛・買掛** — 発生時に `売掛金 / 売上`、入金時に `預金 / 売掛金`。取引先別の残高と未回収一覧。期中は現金主義で記帳し、期末だけ未収・未払を計上する運用も選べる。

**F5-2 定期売上プラン** — 月謝・会費・顧問料・保守料など毎月決まった売上を管理する（Excel 帳簿の月謝管理を汎用化）。

- 顧客ごとにプラン（名称、金額、周期、開始/終了月、状態: 有効・休止・終了）を登録。
- 入金登録: 顧客を選ぶと金額が入り、対象月を付けて仕訳化。返金は売上のマイナスとして登録。
- 月次一覧: 顧客 × （予定額 / 入金 / 返金 / 差引 / 状態）。年間マトリクスで未入金を強調。
- 顧客未指定の一括売上計上も許容し、「未割当の入金」として別枠表示する。

### F6. 決算

**F6-1 期首残高** — 初年度のみ手入力。貸借が一致しないと確定できない。開業初年度は開業費・元入金の入力ガイドを出す。

**F6-2 固定資産と減価償却**

- 資産ごとに: 名称、科目、取得日、取得価額、耐用年数、償却方法、事業専用割合、期首簿価、除却・売却日。
- 対応する償却: 定額法（既定）、定率法（届出がある場合）、一括償却資産（3 年均等）、少額減価償却資産の特例（青色・30 万円未満の即時償却）、月割計算、備忘価額 1 円。
- 年次で償却費を計算し決算仕訳を生成（確認後に確定）。事業専用割合に応じて経費と事業主貸に分ける。
- 耐用年数は主要資産の一覧から選択できるようにする（表はアプリに同梱し、年度ごとに更新可能なデータとして持つ）。

**F6-3 棚卸** — 期末商品棚卸高を入力すると、売上原価（期首棚卸 + 仕入 − 期末棚卸）を計算し、翌期首へ繰り越す。在庫の数量管理はしない。

**F6-4 決算整理チェックリスト** — 未収・未払・前払・前受の計上、家事按分の確定、減価償却、棚卸、貸倒引当金、現金・預金残高の実査照合、事業主貸借の確認。項目は申告区分と有効な機能に応じて出し分ける。

**F6-5 決算書の金額一覧**

- **青色申告決算書（一般用）**: 損益計算書（①〜、青色申告特別控除前の所得金額まで）、月別売上（仕入）金額、給料賃金・専従者給与・地代家賃・利子割引料・税理士等報酬の内訳、減価償却費の計算、貸借対照表（期首 / 期末）。
- **収支内訳書（一般用）**: 白色申告向け。
- 資産合計 = 負債・資本合計、損益計算書と貸借対照表の所得金額の一致を検証し、不一致なら原因候補を示す。
- 出力は「様式の項目順に並べた転記用の金額一覧（画面 + PDF）」。様式そのものへの印字や e-Tax データ出力は将来課題。
- 様式の行構成は年度ごとのデータとして持ち、様式改定に差し替えで対応できるようにする。

**F6-6 年度繰越** — 資産・負債の期末残高を翌期首へ。`翌期首元入金 = 期末元入金 + 青色控除前所得 + 事業主借 − 事業主貸`。マスタ・定型仕訳・固定資産・定期売上プランは引き継ぐ。

### F7. データ取込・出力

- **汎用 CSV 取込**: 列の対応付け（日付・借方・貸方・金額・摘要…）を画面で指定し、設定を保存して再利用。プレビューと検証（未定義コード、貸借不一致、重複）を必ず挟む。
- **既存 Excel 帳簿の取込**: 第 1 章の様式（番号マスタ + 月別シート）を読むインポータを 1 つ同梱する。他形式は汎用 CSV 経由。
- **明細 CSV 取込（v1.x）**: 銀行・カードの明細 CSV を読み、「文字列が含まれていたらこの科目」という自動仕訳ルールで候補を作る。オフライン要件のため API 連携はしない。
- **出力**: 仕訳・帳票・マスタの CSV、各帳票の PDF。他ソフト移行用に汎用的な仕訳 CSV 形式を用意。
- **バックアップ / 復元**: 暗号化した単一ファイル。終了時の自動バックアップ（世代保持）。

### F8. 設定

事業者情報、申告区分、消費税設定、有効にする機能、表示言語（日 / 英）、和暦 / 西暦、データ保存先、起動時パスワード、業種テンプレートの書き出し。

## 5. データモデル（SQLite）

金額はすべて円単位の整数。

| テーブル | 主な列 |
|---|---|
| `fiscal_years` | year, filing_type（blue65/blue55/blue10/white）, tax_status（exempt/standard/simplified/special20）, status, closed_at |
| `accounts` | id, code, name_ja, name_en, kana, category（asset/liability/equity/revenue/cogs/expense）, statement_line, default_tax_category, default_allocation_rule_id, is_system, is_active, sort |
| `sub_accounts` | id, account_id, code, name_ja, name_en, is_active |
| `purposes` | id, code, name_ja, name_en, default_debit_account_id, default_credit_account_id, default_tax_category, allocation_rule_id, default_partner_id, is_active |
| `partners` | id, code, name_ja, name_en, kana, is_customer, is_vendor, invoice_registration_no, memo, is_active |
| `allocation_rules` | id, name, business_percent, rounding |
| `transactions` | id, fiscal_year, date, kind（normal/allocation/template/depreciation/opening/closing）, entry_mode（simple/grid/compound/import）, memo, created_at, updated_at |
| `journal_lines` | id, transaction_id, line_no, side（debit/credit）, account_id, sub_account_id, amount, tax_category, is_qualified_invoice, purpose_id, partner_id, target_month, memo |
| `templates` / `template_lines` | 定型仕訳。recurrence, day_of_month |
| `recurring_plans` | id, partner_id, name, amount, cycle, start_month, end_month, status（定期売上） |
| `opening_balances` | fiscal_year, account_id, sub_account_id, amount |
| `fixed_assets` | id, account_id, name, acquired_on, cost, useful_life, method, business_percent, opening_book_value, disposed_on |
| `inventories` | fiscal_year, closing_amount |
| `statement_layouts` | year, form（blue_general/white_general）, line_no, label, 対応科目（様式改定に備えデータ化） |
| `month_locks` | fiscal_year, month, locked_at |
| `audit_logs` | id, entity, entity_id, action, before_json, after_json, at |
| `settings` | key, value（既存） |

- 明細は借方行・貸方行を別レコードで持つ（複合仕訳に対応するため）。単一仕訳のグリッド表示は借方 1 行 + 貸方 1 行の取引を 1 行に畳んで見せる。
- 既存の `incomes` / `expenses` テーブルは廃止し、かんたん入力の取引として `transactions` / `journal_lines` に統合する。
- 集計値（月次合計・残高）は保存せず、常に仕訳と期首残高から計算する。

### 計算ルール

| 値 | 定義 |
|---|---|
| 取引の整合 | 取引ごとに 借方行の合計 = 貸方行の合計 |
| 資産の残高 | 期首 + 借方計 − 貸方計 |
| 負債・資本の残高 | 期首 + 貸方計 − 借方計 |
| 収益 / 費用の期間額 | 貸方計 − 借方計 / 借方計 − 貸方計 |
| 売上原価 | 期首棚卸 + 仕入 − 期末棚卸 |
| 青色控除前所得 | 収益計 − 売上原価 − 経費計 |
| 按分 | 事業分 = 端数処理(支払額 × 事業割合)、家事分 = 支払額 − 事業分 |
| 定期売上の受取額 | 対象顧客・対象月の売上計 − 返金計 |

## 6. 非機能要件

- **オフライン**: ネットワーク接続なしで全機能が動く。外部送信なし（自動更新は無効化できること）。
- **データ保護**: DB は SQLCipher で暗号化（既存依存を利用）。バックアップも暗号化。ログに個人名・金額を出さない。
- **整合性**: 取引の登録・按分・決算仕訳の生成は DB トランザクションで実行。貸借一致を制約と自動テストで保証。
- **性能**: 年 1 万取引でも入力・集計とも体感待ちなし。
- **制度変更への追従**: 決算書の行構成、税率、耐用年数表、控除額はコードに埋め込まず年度別データとして持つ。
- **i18n**: 全ラベル・帳票見出しを日英対応。マスタ名称は日英 2 項目。
- **対応 OS**: `docs/PLATFORM_SUPPORT.md` に従う。
- **テスト**: 計算ロジック（集計・按分・償却・棚卸・繰越）は Vitest で単体テスト。第 1 章の 2014 年帳簿を取り込み、年次集計が一致することを受け入れテストの 1 つにする（個人名は匿名化したフィクスチャを使用）。

## 7. 既存実装からの移行方針

- `features/income`（単式の収入記録）は `features/journal` に統合し、かんたん入力の 1 モードとして残す。構成は現行どおり `*.model.ts` / `*.service.ts` / `hooks/`。
- 追加する feature: `setup`（初期設定）、`master`、`journal`、`ledger`（帳簿・集計）、`closing`（決算）、`tax`（税区分）、`receivable`（売掛・定期売上）、`import-export`、`backup`。
- DB アクセスは Electron メインプロセス側に置き、レンダラーからは IPC 経由で呼ぶ。

## 9. 確認したい事項

1. **想定ユーザーの簿記レベル**: かんたん入力を主にするか、仕訳グリッドを主にするか。初期画面と用語（借方/貸方を見せるか）が変わる。
2. **白色申告・簡易簿記（10 万円控除）への対応**: v1 から必要か、まず青色・複式（65 / 55 万円）に絞るか。
3. **消費税**: v1 は「税区分を記録するだけ」でよいか。課税事業者向けの集計表まで v1 に入れるか。税抜経理は不要という前提でよいか。
4. **決算書の出力形態**: 転記用の金額一覧で足りるか。e-Tax 用データ出力（65 万円控除の要件に関わる）を将来必須とするか。
5. **同梱する業種テンプレート**: 最初に用意する業種と、その科目・摘要の監修を誰がするか。
6. **配布形態**: 自分用 → 身近な事業主に配布 → 一般公開、のどこまでを想定するか。サポート・制度改定への追従の重さが変わる。
7. **1 つのアプリで複数の事業者データを扱うか**（データファイルの切替）。
8. **対応 OS**: 現状 Windows は WSL2 前提だが、一般の個人事業主向けならネイティブ対応が必要になる。
